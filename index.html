学习笔记11

DNS劫持：
四种主要攻击方式：
1.终端本地劫持
修改操作系统 DNS 服务器地址，全部解析请求发送到攻击者 DNS 服务器；
修改hosts文件，hosts 优先级高于 DNS，直接写死域名指向恶意 IP，不走网络 DNS 查询。

2.路由器 DNS 劫持

攻击者利用路由器弱口令、路由器漏洞登录管理后台，修改路由器 WAN 口 DNS，填入恶意 DNS 服务器地址。
连接这个 Wi‑Fi 的所有手机、电脑全部中招。

3.中间人劫持

公共免费 WiFi 环境，攻击者做 ARP 欺骗，拦截内网 DNS 请求；不等合法 DNS 返回，抢先回复伪造 IP 报文。
不需要修改任何设备配置，只要连这个 WiFi 就中招。

4.服务器端劫持
入侵运营商递归 DNS 服务器、域名权威服务器，直接修改解析记录，会影响成千上万用户，攻击门槛很高。

典型受害现象：
1.浏览器地址栏域名完全正确，页面却是广告、赌博、钓鱼网站。
2.访问 HTTPS 网站弹出证书错误警告（假冒网站拿不到合法证书）。
3.QQ、微信可以登录，网页打不开；聊天软件内置 IP 库，不走 DNS 解析。
4.网页自动弹窗、强制跳转。

风险危害：

1.钓鱼网站窃取账号密码。
2.诱导下载木马病毒。
3.注入广告，篡改网页内容。
4.企业内网环境下，劫持业务域名造成内网系统被冒充。

学习笔记10

APT 属于高等级网络攻击
APT 完整攻击链路（深度流程）
侦察阶段：
攻击者大量搜集目标公开信息：员工邮箱、社交账号、官网文档、业务系统版本，摸清内部细节，定制攻击方案。
常用手段：
鱼叉钓鱼邮件
利用 0day 漏洞
供应链攻击
立足潜伏
入侵一台主机后，不会立刻乱搞。
在机器上留后门，清除系统日志，掩盖入侵痕迹，修改权限，伪装成正常系统进程，杀毒软件很难发现。
APT核心特征：横向移动
拿下一台电脑只是起点。
在内网里扫描其他主机，窃取账号密码，利用域权限，一台一台往服务器、数据库渗透，不断扩大控制范围，在内网到处 “游走”。
数据收集与外渗：
偷偷拷贝图纸、数据库、机密文档，把加密后的数据，通过伪装成正常网络流量，偷偷传到攻击者服务器。全程尽量不触发告警。
行动：
时机到了，要么窃取大量数据带走；也可以搞破坏（删数据、破坏工业控制系统）；最后清理痕迹，销毁入侵日志，悄悄撤离。
防御思路：
内网分段隔离
监控日志
限制高权限账号
警惕鱼叉钓鱼
定期威胁狩猎

学习笔记9

BOM：操控浏览器窗口本身（地址栏、弹窗、刷新、前进后退、定时器）
DOM：操控网页页面内容（文字、图片、按钮、样式、标签结构）
二者顶层都是 window 对象，浏览器打开页面就自动生成 window，所有属性都挂载在它身上。 DOM 树结构：
window
└── document（文档根节点）
├── html
├── head
└── body
├── div
├── p
├── button

页面每一个标签、文字、注释，都是一个节点 node。
BOM含五大核心对象：
window、location、history、navigator、screen
类别 操控对象 核心作用 典型内容
DOM 网页 HTML 文档 修改页面内容、样式、结构 获取标签、改文字、绑定点击事件、创建列表
BOM 浏览器窗口 操控浏览器软件本身 定时器、跳转网址、刷新、前进后退、窗口滚动、本地存储

学习笔记8

木马全称特洛伊木马，名字源自古希腊特洛伊战争的木马计。
它本身不会自我复制传播（这点和普通电脑病毒不一样），外表伪装成正常文件，一旦你主动点开、安装运行，就会悄悄潜入电脑设备，偷偷窃取信息、操控设备。
木马和普通病毒的区别：

普通病毒：主打自我复制、破坏文件、拖慢系统，会到处传染；
木马：没有大肆传染能力，目的大多是偷资料、远程控制、盗取账号钱财，隐蔽潜伏。
木马常见伪装样式：
日常最容易碰到的几类：
文档、压缩包
社交软件中发来：简历、成绩单、照片压缩包、财务表格等
工具类文件：
壁纸、字体、资源素材、绿色版软件。
捆绑木马原理：
黑客把正常软件 / 图片 / 文档和木马病毒程序打包合并成一个文件，你双击打开看似运行了正常内容，暗地里木马同步悄悄启动，这就叫文件捆绑。
好比一个礼盒：
外层包装印着好看的图案（你想要的游戏、壁纸、补丁）；
礼盒里面分两层：上层是你想要的东西，底层偷偷藏了小偷（木马）；
你拆开礼盒翻看礼物时，底下的小偷趁机溜进你家里（电脑后台）躲起来。

学习笔记7

零知识证明：
通俗来讲，零知识证明就是我让你相信我说的一句话或一个结论而不需要向你透露任何有关该结论的有用信息。
零知识证明有三大核心特性：
第一，完备性（Completeness）：
真的陈述，诚实执行必被接受（∀x∈L, Pr[接受]=1）。
第二，可靠性（Soundness）：
假的陈述，作弊成功概率 ≤ negl(λ)，可忽略；更强地，若能骗过，则必存在抽取器 E 提取出 w——即知识可靠性（PoK）。
第三，零知识（Zero-Knowledge）：
验证者除”命题为真”外一无所获；严格地，存在模拟器 S 造出与真实交互不可区分的记录。
举个简单的例子：
Alice 手里藏着一个秘密数字：密码 = 73
Bob 要确认：Alice 确实知道这个数字，但绝对不能让 Bob 得知数字是多少。
1.交互式零知识证明：
规则前置：
我们规定一道运算：
数字 x 经过固定公式计算后，结果永远等于 200
公式：x + 127 = 200
只有 x=73 能满足式子。
交互步骤
Alice 提前算出结果，私下准备好，不告诉 Bob 数字；
Bob 随机出题考验 Alice，两种指令随机选其一：
指令 A：你告诉我运算最终结果
指令 B：你把你的数字带入公式演算一遍
一轮过程：
假如 Bob 喊指令 A：Alice 回复最终得数 200
假如 Bob 喊指令 B：Alice 完整演算，结果依旧是 200
为什么骗不了人？
如果 Alice 根本不知道数字，只能瞎蒙：
每一轮猜对概率只有 1/2
连续 20 轮全部答对，蒙混过关概率：≈百万分之一，基本可以认定没有作假。
最终效果
Bob 全程不知道数字是 73，但是百分百确定：Alice 拥有正确数字。

JS 全称：JavaScriot，简称 JS
JS 负责交互逻辑（切换文字，轮播图，表单验证，弹窗，数据请求等）
JS特点：
弱类型语言：不用提前规定变量类型
解释型：浏览器直接运行，不需要编译
既能跑浏览器，也能跑服务器
声明变量三种方式
1 var：
var name = “张三”;

2 let：
let age = 18;
age = 数值;

3 const：
const PI = 3.1415;（常量）
命名规则：
不能以数字开头
不能是 JS 关键字：let、const、if、for、function 等
区分大小写

学习笔记5

CSS：负责网页样式与外观
文件后缀：.css，可以写在 HTML 标签内、页面头部、独立 css 文件
内部样式表
写在 html 的 style 标签中，放在head里面，当前整个页面生效
html
head
style
div {
color: blue;
}
style
head
CSS 语法格式：
选择器 {
属性名: 属性值;
属性名: 属性值;
}
选择器：选中要改样式的 HTML 标签
属性：要修改的样式（颜色、大小）
属性值：样式的具体设置
每一条以 ;结尾
CSS 单位：
px：像素，固定大小，最常用
%：百分比，相对于父盒子大小
rem：相对于 html 根标签字体大小，移动端适配用
em：相对于自身字体大小
多个选择器选中同一个标签，看权重大小，大的覆盖小的
通配符*：0
标签选择器：1
class 类选择器：10
id 选择器：100
行内 style：1000

学习笔记4

一、基础网页骨架：
DOCTYPE html
声明文档类型
html lang=”zh‑CN”
html：lang=”zh‑CN” 代表网页语言是中文 

<head：网页头部，存放页面配置，内容不会显示在页面上 
<meta charset="UTF‑8">
<!-- meta字符集：设置编码，防止中文乱码，必须写 -->
<title>我的第一个网页</title>
<!-- title：浏览器标签页上面显示的标题 -->

head
body
body：网页主体，所有看得见的内容全部写在这里！！
这里写页面内容

二、常用标签分类：
标题标签 h1 ~ h6
h1 最大，h6 最小，有语义，代表标题
三、网页里面要用字符，不能直接打空格：
空格： nbsp;
小于： lt;
大于： gt;

各类元素：

1、块级元素 block
特点：独占一行，可以设置宽高
代表：div h1~h6 p ul ol li header main footer

2、行内元素 inline
特点：一行多个并排，不能设置宽高，大小跟随内容
代表：span a b em strong

3、行内块 inline‑block
特点：一行多个并排，可以设置宽高
代表：img input textarea

❌HTML 常见坑
忘记写 </>闭合标签，页面布局乱掉。
img 的 src 路径写错，图片不显示。
表单 input 不写 name，提交拿不到数据。
单选框 radio 的 name 不相同，结果可以同时多选。
中文页面忘记写出现乱码。

Hexo写新文章+发布步骤

一、新建博客文章
打开 CMD，定位在 D:\myblog
执行这条命令创建文章：
bash
运行
hexo new “文章标题”
文件位置
生成的文章在这里：
D:\myblog\source_posts\你的文章标题.md
用记事本 / VS Code 打开这个 .md 文件。
书写规则
文件顶部是文章配置（不要删除）
markdown
title: 我的第二篇博客
date: 2026-07-29 18:00:00
tags: [学习,Hexo]
categories: 随笔

这里下面写正文内容，使用Markdown语法
可以写文字、插入图片、列表等
— 上面是配置，下面才是网页展示的正文。写完保存文件。
二、本地预览（推荐！先看效果再发布）
CMD 执行：
bash
运行
hexo g && hexo s
浏览器打开 http://localhost:4000
查看你的博客，确认排版、图片没有问题。
三、生成静态网页 + 推送到 GitHub 上线（核心发布流程）
以防hexo d 会卡住，使用这套稳定命令
bash
运行
hexo clean && hexo g
cd public
git add .
git commit -m “新增文章：xxx”
git push -f origin gh-pages

终端最后一行：

  • [new branch] gh-pages -> gh-pages
    代表网页文件已经全部上传到 GitHub 仓库的 gh-pages 分支。
    步骤拆解
    hexo clean && hexo g：清理旧网页，重新生成全部网站文件
    cd public：进入网页文件夹
    git add .：记录所有改动
    git commit -m “描述”：填写更新备注，随便写
    git push -f origin gh-pages：强制推送到 GitHub 博客分支
    1.点击页面上方 Settings
    2.在左侧找到 Pages
    3.配置：
    Source：Deploy from a branch
    Branch：选择 gh-pages
    Folder：/(root)
    点击保存(save)。

    四、等待网站更新
    推送命令跑完没有报错，等待 3～10 分钟
    无痕浏览器打开：你所建立的博客网址， 查看新文章。
    常用小提示
    如果想删除文章：
    直接删除 source_posts 对应的 .md 文件，再完整执行一遍发布命令；
    tag 标签、分类写错，直接修改 md 文件内顶部内容；
    不要手动修改 public 文件夹内文件！
    public 是自动生成的，所有修改只能在 source_posts 里操作。
    五、更新博客固定流程（保存备用）
    CMD 执行：
    bash
    运行
    hexo clean && hexo g
    cd public
    git add .
    git commit -m “更新文章”
    git push -f origin gh-pages
    推送完成后等待几分钟，网站自动更新。
